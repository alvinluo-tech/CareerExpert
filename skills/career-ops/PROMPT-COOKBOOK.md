### 场景 1：增量补充开源项目、GitHub 仓库与在线演示链接

- **适用情境**：用户在求职过程中新做了一个项目、上线了开源库或部署了个人在线作品集，希望补入简历。
- **推荐用户指令 (User Prompt)**：
  > “我最近新开源了一个项目叫 FastFlow，仓库地址是 `https://github.com/myname/fastflow`，在线演示在 `https://fastflow.dev/demo`。这是基于 Go 语言的高性能流式中间件，单节点压测吞吐量达到 18.5 万 QPS，内存比常见框架降低 42%，目前收获了 1.2k Stars。请帮我把这个项目增量补充进简历素材库，并根据这个中间件专家 JD 重新生成一份高匹配度的单页简历，超链接在 PDF 中要能正常点击且排版优雅。”
- **Agent 执行策略与红线约束**：
  1. 调用 `python scripts/append_fact.py project ...` 先将用户提供的项目、链接与数据增量安全落盘至 `profile/projects/fastflow.md`，并在 `profile/basic.md` 建立引用；
  2. 严禁凭空添加用户未提及的 Star 数或虚构数字；
  3. 在 HTML 模板中使用优雅的超链接样式（带有微胶囊标识与悬停反馈），确保打印/PDF 渲染后超链接保持高质感；
  4. 重新编译 PDF 并运行 `check_facts.py` 确保 100% 可追溯。

### 场景 2：基于特定目标 JD 重新靶向调整简历重点

- **适用情境**：用同一份底层经历，投递偏“业务中台架构” vs 偏“底层基础架构”的不同岗位。
- **推荐用户指令 (User Prompt)**：
  > “这是我刚看到的目标岗位 JD（附后），这家公司特别看重‘流式数据实时处理’与‘内核级零拷贝内存优化’。请读取我的 profile 素材库，按该 JD 的核心能力模型重新筛选经历，优先把最对口的流式项目放第一位，并把 bullet 重点向零拷贝与延迟优化靠拢。”
- **Agent 执行策略与红线约束**：
  1. 执行 `jd-eval` 逻辑，分析 JD 提取一级核心关键词；
  2. 调整经历展示优先级：匹配度最高的项目前置；
  3. 将经历中已有的真实事实用对应专业术语重新重组（Reframing），杜绝编造。

### 场景 3：弱动词强力改造为 Google XYZ 战果量化

- **适用情境**：简历写得像岗位职责流水账（“负责维护...”，“参与开发...”）。
- **推荐用户指令 (User Prompt)**：
  > “/career-polish 请帮我把工作经历里的第 2 段和第 3 段重度润色。把所有的弱动词（‘参与/负责’）全部替换为技术决策强动词，严格套用 Google XYZ 公式（Accomplished X as measured by Y by doing Z），关键指标粗体高亮，不要修改版面样式。”
- **Agent 执行策略与红线约束**：
  1. 激活 `career-polish` 技能，锁定 HTML/CSS 样式；
  2. 每一条改写输出 `[Before 原句]` -> `[After 改写]` -> `[改写依据]` 留痕记录；
  3. 运行 `check_facts.py` 确保数字与素材库完全吻合。

### 场景 4：单页微溢出救急 (超出一两行掉到第2页)

- **适用情境**：内容稍多，无头浏览器导出时多出半寸，导致变成 1.1 页尴尬排版。
- **推荐用户指令 (User Prompt)**：
  > “/career-style 当前简历导出的 PDF 变成了 2 页，第 2 页只有 3 行。请启动单页预算压缩机制（ultra-dense / compact），帮我微调行高、字距或页边距，严格压制成一页纸，且保证内容不被截断、填充率在 90% 以上。”
- **Agent 执行策略与红线约束**：
  1. 将 `style.yml` 中的 `density.level` 切换为 `compact` 或 `ultra-dense`；
  2. 微调字号至 9.5pt 或 9.0pt，段落间距调整为 6pt~8pt；
  3. 运行 `render_pdf.py ... --max-pages 1`，脚本将自动验证页面截断并给出单页黄金填充率。

### 场景 5：应届/转行经历精简防大片留白 (充实版面)

- **适用情境**：应届本科生或转行初期，项目只有 1~2 个，单页只占了 60%，底部留白难看。
- **推荐用户指令 (User Prompt)**：
  > “/career-style 我是应届生，经历比较精简，目前简历看起来下半部分很空。请切换为 airy 从容舒展排版，把教育背景前置第一屏，展开核心课程与专业竞赛，把我的科研项目背景、难点与收获完整叙述，使页面充实饱满，单页填充率达到 85% 左右。”
- **Agent 执行策略与红线约束**：
  1. 设定 `density.level: airy`（正文 10.5pt，行高 1.56，节间距 14pt）；
  2. 调整 `sections` 顺序为 `education -> projects -> work/internship -> skills -> awards`；
  3. 充实 bullet 的技术决策与学习反思细节，消除空旷感。

### 场景 6：无照片 -> 插入经典真实证件照

- **适用情境**：外企投行通常不需要照片，但国内国企、私企或出海商务总监需要高管商务形象照。
- **推荐用户指令 (User Prompt)**：
  > “请在简历右上角（或左侧边栏）加入我的职业形象照，照片路径为 `profile/photo.jpg`，采用经典 3:4 证件照比例，边角微圆角，旁边对齐基本信息。”
- **Agent 执行策略与红线约束**：
  1. 检查本地照片路径是否存在；
  2. 配置模板中的 `.photo-box` 样式，严格设置 `aspect-ratio: 3/4` 与 `object-fit: cover`；
  3. 重新渲染 PDF 与预览图，核验照片与文字基线对齐。

### 场景 7：视觉风格大变身 (经典细线 -> 现代双栏侧边栏)

- **适用情境**：希望从传统的黑白文字流升级为具有现代设计感、左右分工明晰的高级 UI 简历。
- **推荐用户指令 (User Prompt)**：
  > “我想换个更具现代科技感的版面。请帮我切换成 v8 双栏侧边栏模板（v8-sidebar-split），主题色采用科技墨绿（#0f766e），左侧栏放头像、基本信息、技能胶囊和语言资质，右侧主栏放核心工作经历和项目，左右单页高度齐平。”
- **Agent 执行策略与红线约束**：
  1. 应用 `resume-template-v8-sidebar-split.html` 骨架；
  2. 映射 CSS 变量 `--accent: #0f766e`；
  3. 校验左侧栏内容体量与右侧主栏的高度平衡，避免一长一短失衡。

### 场景 8：突出团队管理与跨部门商业交付

- **适用情境**：技术骨干晋升 Team Lead / 技术总监，需要从“纯写代码”转变为强调“团队效能与跨部门商业闭环”。
- **推荐用户指令 (User Prompt)**：
  > “我这几年除了写核心模块外，其实还带了 8 个人研发团队，并协同产品、运维团队完成了核心版本交付。请帮我改写这部分，重点突出团队管理跨度、敏捷研发效能提升与按期交付率，体现 Leader 视野。”
- **Agent 执行策略与红线约束**：
  1. 梳理真实带人规模（严格核对事实）；
  2. 提取管理动词（“统筹带领 8 人敏捷团队”、“制定代码评审规范”、“重构 CI/CD 交付链路”）；
  3. 给出效能提升指标（“核心版本按期交付率提升至 98%”、“线上事故率下降 60%”）。

### 场景 9：外企与跨国 Remote 岗位英文/开源特化

- **适用情境**：投递 Stripe、GitLab、Automattic 等全英文 Remote 团队。
- **推荐用户指令 (User Prompt)**：
  > “我要投递一家海外全远程（Remote）团队，他们特别看重异步沟通、开源贡献和英文文档规范。请帮我把简历重点强化：突出 GitHub 开源项目链接、文档编写能力与异步代码评审经验，格式采用美式标准无照片极简风。”
- **Agent 执行策略与红线约束**：
  1. 选用美式标准的无照片经典款；
  2. 将开源贡献、RFC 技术提案设计与异步协同（Async Collaboration）作为核心卖点；
  3. 超链接格式化为干净易读的文本样式。

### 场景 10：针对特定标杆项目进行模拟技术面试攻防

- **适用情境**：简历制作完成，开始准备即将到来的高难度大厂技术面试。
- **推荐用户指令 (User Prompt)**：
  > “/career-interview 针对我简历里写的 FastFlow 流式引擎项目，假装你是字节跳动/阿里云的基础架构面试官，对我进行 3 轮由浅入深的压力提问。先别给我答案，等我回答后你再逐轮点评并给出最佳回答示范。”
- **Agent 执行策略与红线约束**：
  1. 激活 `career-interview` 技能，进入【L1 基础探针 -> L2 机制拷打 -> L3 架构极限】四级递进攻防；
  2. 严格遵循“一次只问一个问题”，等待用户输入；
  3. 结合用户回答指出漏洞并给出高分复盘。

### 场景 11：查阅改写前后的逐条 Diff 对比报告

- **适用情境**：用户想清晰了解 AI 究竟改动了哪些文字、理由是什么、是否有编造。
- **推荐用户指令 (User Prompt)**：
  > “请给我一份详细的 Before/After 改写对比报告，列出修改前后的原句、修改理由以及每条数据在 profile 素材库中的具体出处。”
- **Agent 执行策略与红线约束**：
  1. 输出 Markdown 格式的 Diff 报告；
  2. 对比每一处动词、量化指标的演进；
  3. 附带 `check_facts.py` 的执行通过证据。

### 场景 12：海外名校硕博学术 CV 顶会文献悬挂缩进

- **适用情境**：申请海外顶级博士（PhD）或终身教职。
- **推荐用户指令 (User Prompt)**：
  > “/career-cv 我正在申请 Stanford/MIT 计算机博士，请按照 Harvard Academic CV 标准为我排版一份严格双页的学术 CV。顶会论文需支持 IEEE 悬挂缩进、导师与合作者清晰列明，排版严禁使用商业公司的彩色图标。”
- **Agent 执行策略与红线约束**：
  1. 启用 `v7-academic-cv` 模板；
  2. 出版物使用经典悬挂缩进（Hanging Indent 0.25in）；
  3. 严格限制为 2 页，两页填充率均保持在 85%~95% 之间。
