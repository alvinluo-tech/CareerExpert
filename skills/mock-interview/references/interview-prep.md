# 面试准备与模拟

> 本文件是 job-finding 技能的参考文档,由 SKILL.md 按需加载;路径均相对仓库根。

两种模式,用户开口即选,不明确就先问。

## 模式一:针对性准备(产出 `applications/interviews/<公司>-<岗位>.md`)

1. 读该 JD 评估报告(F 块的 STAR 预判)+ 全部 star-bank + 相关项目卡。
2. 若无公司调研:搜索公司近况(产品、技术博客、新闻、融资/裁员),
   区分"确认事实"与"网络说法",标注来源与日期;查不到就明说。
3. 产出准备文档:
   - 高概率问题清单:按 技术考察点 / 系统设计 / 行为题 / 反问环节 分组
   - 每道行为题映射 star-bank 中的故事(映射,不新编);
     star-bank 覆盖不到的 archetype → 提示用户补录
   - 简历自审:这版简历上每一条 bullet,面试官最可能深挖什么?
     哪些 bullet 的数字自己讲不清 → 红色预警(投前就该修)
   - 反问建议 3~5 条(基于调研,不泛泛)
4. 更新 tracker 该行状态与下一步。

## 模式二:模拟面试

角色扮演面试官,结构参照成熟开源面试 agent 的设计:

1. **阶段固定**:暖场 1~2 题 → 核心考察 → 追加压力/深挖 → 收尾点评。
2. **深挖是职责**:模拟真实面试官,对含糊回答追问细节(数字怎么测的?
   你个人做了什么?)——这同时是对简历事实性的压力测试。
3. **四级提示阶梯**(用户卡住时,逐级给,不跳级):
   L1 方向性提醒 → L2 点名方法/模式 → L3 部分解法 → L4 完整思路。
   学习发生在挣扎处,先给 L1。
4. **结束必给评分卡**:按维度(如 需求澄清/权衡分析/表达结构/深度)打分
   + 各一句证据 + 最优先改进项 1~2 条。
5. **收尾回写**:实际暴露的薄弱点回填 `profile/` 对应素材卡"可讲细节"
   和 star-bank"实战记录"。这一步让每次模拟都沉淀进素材库。

边界:不替用户编故事;用户答不上来的故事要么简化要么从 star-bank 删除,
带着讲不清的简历上战场是最大风险。
