# 简历内容质量指南 — 权威信源综合版

> 供 resume-tailor skill 的内容门禁引用。只收权威或被广泛验证的信源,
> 每条标注可信度;与 skill 的策略包(strategy-packs.md)配合使用:
> 本文件是"所有领域通用的质量底线",策略包是"领域/招聘类型差异"。

## 1. bullet 写作公式(最高优先级)

- **Google XYZ 公式**(信源:Google 官方招聘建议,出自 Laszlo Bock《Work Rules!》,
  Google 前人力运营 SVP;可信度:高,有官方出处):
  **"Accomplished [X] as measured by [Y], by doing [Z]"**
  = 做成了什么(成果)+ 用什么衡量(量化)+ 怎么做的(动作)。
- **HBS PAR 结构**(信源:HBS 校友职业资源 + HBS CMC;可信度:高,官方机构):
  问题 → 行动 → 结果;每条以**强动作动词开头**,接职责范围,接量化影响。
- 无精确数字时的替代(信源:社区共识,可信度:中):
  用规模/范围代替——"服务 40+ 接入方""支撑日订单峰值 150 万"
  也是量化;完全没有数字的 bullet 降权处理(放后、删减)。

## 2. 量化:普适但"量什么"不同(信源:ResumeWorded/Indeed 汇总;可信度:中高)

| 领域 | 量化的对象 |
|---|---|
| 金融 | 资金规模、收益率、成本节约、交易额、P&L |
| 工程/技术 | 延迟、吞吐、可用性、成本、效率、规模(QPS/行数/设备量) |
| HR/人事 | 招聘量、time-to-fill、留存率、覆盖率、培训人数、人效 |
| 通用商业 | 收入、增长%、市场份额、客户数、NPS |

## 3. 写作红线(反模式清单)

- **职责型语句**("负责 XX 系统")→ 必须改写成成就型(做了什么改变、带来什么结果)
- **弱开头**("参与""协助""帮助"单独开头)→ 换强动词并写清个人贡献边界
- **空话形容词**("富有激情""抗压能力强""精通"滥标)→ 删;技能水平如实标注
- **无结果的动作**("重构了网关"没说结果)→ 补量化或影响
- **代词与主语冗余**(中文简历"我做了…"→ 直接动词开头)
- 信源:r/EngineeringResumes wiki(社区信源但为工程师招聘方向公认质量最高的
  简历标准之一)、HBS 指南;可信度:高(交叉验证一致)

## 4. 长度与取舍

- 一页:10 年以内经验的主流默认;**金融(尤其 IB/校招)是一页铁律**
- 两页可接受:资深候选人有大量项目/专利/发表;工程领域接受度高于金融
- 信源:Mergers & Inquisitions(金融,高)、Ivy Exec(中)
- 每条 bullet 与目标 JD 的相关性排序:最相关的放最前(本项目已有机制)

## 5. 结构与模块(与策略包配合)

通用顺序骨架:联系 → 概述(可选)→ 经历 → 项目 → 技能 → 教育,
但**顺序由招聘类型决定**(校招教育前置)、**模块取舍由领域决定**
(工程必有技术技能区;金融可省"项目"加"领导力经历";HR 突出职能覆盖)。

| 信源 | 类型 | 可信度 | 使用方式 |
